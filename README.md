# EDUS · Библиотека

Интерактивный frontend сенсорного библиотечного терминала. Vue 3, Vite, TypeScript. Все читатели, остатки и операции демонстрационные; нет подключений к платформе EDUS, модулю питания или оборудованию.

## Запуск

Требуется Node.js 24 LTS и npm. Из каталога проекта:

```bash
npm ci
npm run dev
```

Рабочий интерфейс: http://127.0.0.1:5173/

## Целевой терминал

Основной профиль — **10,1″ / 1280×800 / 16:10 / горизонтальный touch POS / Ubuntu + Chromium kiosk / 100% масштаб страницы**. Это целевое разрешение важнее крупных референсных макетов. Интерфейс не использует общий CSS zoom, `transform: scale`, фиксированный контейнер шириной 1280px или скрытое переполнение для имитации размещения. Полный профиль: [SPEC.md](SPEC.md). Визуальные правила: [DESIGN.md](DESIGN.md).

- Галерея компонентов и состояний: http://127.0.0.1:5173/#/components
- Второй экран читателя: http://127.0.0.1:5173/#/display — открыть отдельным окном на том же origin.

Проверки и сборка:

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

`preview` открывает production-сборку на http://127.0.0.1:4173/. Никакая команда не публикует проект наружу. Vite слушает только loopback; настройки Ubuntu не затрагиваются.

Браузерный прогон и экспорт PNG:

```bash
node scripts/qa-identify-reference.mjs
# Проверка целевого 10,1″ терминала:
node scripts/qa-kiosk-1280.mjs
# Только одно разрешение:
node scripts/qa-identify-reference.mjs --viewport=1536x1024
# Дополнительный полный регрессионный прогон:
node scripts/qa-browser.mjs
```

Скрипт использует уже установленный в Codex Chromium/Playwright и Sharp. На другой машине задайте `CODEX_NODE_MODULES` как путь к каталогу, где доступны `playwright` и `sharp`; `EDUS_QA_URL` меняет адрес приложения. Эти инструменты не входят в runtime frontend. Скрипт создаёт отдельные браузерные контексты, не обращается к пользовательскому профилю и не меняет состояние приложения скрытыми командами.

Предыдущая функциональная итерация 2 от 16 сентября 2026 проверена: TypeScript, lint, 43/43 теста и сборка прошли; основной браузерный прогон — 28/28 сценариев на четырёх viewport и 164 PNG. Адаптированный полный регресс дополнительно прошёл 9/9 сценариев на 1600×900 с 62 PNG. Подробная история: [QA_REPORT.md](QA_REPORT.md), [целевой итог](.qa/iteration2-summary.json), [регрессионный итог](.qa/regression2/browser-summary.json), [обзор экранов](screenshots/iteration2/overview.png). Новые артефакты находятся в `screenshots/iteration2/`, `.qa/iteration2-*.json`, `screenshots/regression2/` и `.qa/regression2/`. Исходные `.qa/browser-*.json` и старые PNG оставлены для исторического сравнения.

## Проверить сценарии

На главной выберите «Выдать книги», «Принять книги» или «Добавить книги». Для имитации карты или сканирования откройте шестерёнку → «Панель сценариев». Панель по умолчанию свёрнута и не занимает рабочий экран. Ручные поиск и ввод доступны без неё.

Выдача и **любой приём** сначала открывают идентификацию: «Кому выдаём книги?» или «Кто возвращает книги?», инструкция «Приложите карту ученика», действие «Найти вручную». Сначала выберите читателя, затем сканируйте книги или выбирайте его выдачи. Это правило одинаково для инвентарного номера, индивидуального экземпляра, ISBN и старого фонда. ISBN не определяет владельца. Книга другого читателя отклоняется с сохранением текущего списка; перейти к другому читателю можно явным действием и с согласием на очистку заполненной корзины. Начало новой операции очищает предыдущую сессию.

| Значение | Назначение в начальном учебном фонде |
|---|---|
| `EDUS-1001` | Сәрсенова Айша Ерланқызы, 7 «А» |
| `EDUS-1002` | Нұрланұлы Әлихан, 8 «Б» |
| `000124` | Доступный экземпляр «Алгебра. 7 класс» |
| `000125` | Доступный экземпляр «Қазақ тілі. 7-сынып» |
| `000123` | Экземпляр на руках у Айши |
| `KZ-0007` | Экземпляр «Абай жолы» на руках у Әлихана |
| `9786010123456` | ISBN «Қазақстан тарихы», старый фонд |
| `DEMO-MULTI` | Несколько подходящих изданий |
| `BOOK-NOT-FOUND` | Неизвестный код |

Учебные операции меняют реальные данные mock-адаптера и сохраняются в `localStorage`. Поэтому после выдачи `000124` он уже недоступен для повторной выдачи, пока его не примут. Для воспроизводимых проверок браузерный скрипт создаёт отдельные чистые контексты. Данные основного пользовательского окна он не меняет.

Набор символов с завершающим Enter вне текстовых полей обрабатывается как ввод сканера. Ввод в активное текстовое поле сохраняет фокус. Пока открыта помощь, сканер приостановлен. Это поддержка keyboard-wedge поведения, не подтверждение наличия реального сканера/NFC.

Знак «?» на идентификации открывает правую панель «Как это работает?» с тремя шагами; на узком экране это диалог. Крестик или Escape закрывают её и возвращают фокус. На остальных экранах сохранены прежняя справка и «Понятно». Читатель и корзина сохраняются. Если ответ карты пришёл за открытой справкой, переход выполняется после закрытия; отменённый запрос не выбирает читателя. Интерфейс русскоязычный. Выбор языка экранной клавиатуры меняет только раскладку ввода.

## Системные состояния

В настройках независимо переключаются моделируемые локальный сервер и интернет; там же доступна диагностика. Постоянная нижняя строка технических статусов убрана. Недоступность API/локального сервера отображается в затронутом сценарии, сохраняет корзину и препятствует неподтверждённой операции; потеря интернета позволяет продолжать локальную работу. Панель сценариев позволяет задержать ответ, вызвать ошибку следующей операции и приостановить сессию.

Неизвестный результат проверяется по идентификатору операции; повторная отправка с экрана неопределённости отсутствует. Данные восстановления сохраняются в браузере. При пяти минутах бездействия незавершённая сессия приостанавливается без очистки корзины.

Второй экран только читает короткий снимок через `BroadcastChannel`: сокращённое имя, список и количество. Он не получает номер карты или ИИН, ничего не сохраняет и очищает завершённую операцию через 15 секунд. При отсутствии сигналов от терминала данные также очищаются.

- `src/composables/useTerminal.ts` — состояние выдачи и приёма.

- `src/views/RegistrationView.vue` — поиск/создание издания и регистрация.
- `src/views/StudentDisplay.vue` — read-only экран читателя.
- `src/views/ComponentGallery.vue` — изолированная галерея.
- `src/styles/tokens.css` — цвета, интервалы, радиусы, локальный шрифт.
- `public/assets/` — исходный логотип, историческая реконструкция синей карты/PNG и лицензированный локальный шрифт. Рабочий экран использует новую светлую векторную схему школьной карты, см. ASSET_MANIFEST.
- `tests/` — проверки правил фонда и состояния терминала.
- `screenshots/` и `.qa/` — полноразмерные снимки и результаты браузерной проверки.

## Границы готовности

Это демонстрационный frontend с проверенными изменениями итерации 2; область проверки зафиксирована в QA_REPORT. Реальный backend, база учеников, авторизация платформы, синхронизация, физические NFC/сканер и Ubuntu kiosk требуют контрактов и отдельной интеграции. Нельзя использовать учебные данные как настоящие выдачи.

ТЗ `SafeSchool_Library_Terminal_SPEC_v1.2.md` и старые библиотечные HTML-прототипы не были найдены. Реализация следует подробному приложенному заданию и более поздним уточнениям пользователя. Исходники `canteen-front-main` на Desktop изучены, но не изменялись. Реконструированный орнамент исторической синей карты не является исходным типографским макетом; активная светлая схема карты орнамента не содержит.

Для реального транспорта дополнительно нужен журнал операции до отправки запроса и серверная идемпотентность. Текущий адаптер моделирует эти результаты локально; после `UNKNOWN` данные восстановления сохраняются. Проверка на Windows Chromium не заменяет проверку на реальном терминале Ubuntu.

Официальные источники совместимости: [Vue Quick Start](https://vuejs.org/guide/quick-start.html), [Vite Getting Started](https://vite.dev/guide/). Точные версии зафиксированы в `package-lock.json`.

Текущий экран идентификации воспроизводит приложенный референс 1536×1024. Общий SVG и экран используются при выдаче и приёме, правая справка открывается по «?». 50/50 unit/state-тестов и 33/33 целевых браузерных сценария прошли; [новые скриншоты и сравнение](screenshots/identify-reference/) и [отчёт](.qa/identify-reference-report.json). Старые `qa-iteration2.mjs` и `qa-line-art.mjs` сохранены как исторические сценарии соответствующих дизайнов; текущая визуальная проверка — `qa-identify-reference.mjs`.


## Production preparation, integration evidence and Ubuntu release

The repository now includes a production-safe boundary and an Ubuntu/static release package. The required library backend was **not** found in the supplied material, so the final production bundle blocks transactions instead of silently operating on the local mock dataset. The development server remains useful for demo and automated UI tests only.

- Evidence and canteen separation: [docs/CANTEEN_INTEGRATION_MAP.md](docs/CANTEEN_INTEGRATION_MAP.md)
- Candidate API boundary, explicitly awaiting server confirmation: [docs/LIBRARY_API_CONTRACT.md](docs/LIBRARY_API_CONTRACT.md)
- Confirmed state and blockers: [PROJECT_STATE.md](PROJECT_STATE.md), [BLOCKERS.md](BLOCKERS.md)
- Ubuntu and school-server instructions: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md), [docs/INSTALL_RU.md](docs/INSTALL_RU.md)
- Production package after a build: `npm run package:release`

A real release still requires the library server contract, terminal authentication policy, LAN test environment, reader/scanner details and Ubuntu hardware acceptance. The supplied canteen card endpoint is deliberately excluded because it belongs to nutrition business logic.
