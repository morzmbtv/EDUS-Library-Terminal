# EDUS Library Cloud 1.1.0 — infrastructure deployment

This package is NOT an end-user Windows application. Deploy separately to approved EDUS infrastructure. PostgreSQL 17, PHP 8.2–8.4 with PDO PostgreSQL, mbstring, openssl, sodium, curl, fileinfo, XML, ctype, tokenizer are required. Included vendor dependencies are pinned production packages; target Linux must satisfy composer check-platform-reqs --no-dev.

1. Place source outside the web root; expose ONLY public/ through Nginx/Apache + PHP-FPM. Configure HTTPS and trusted proxy headers. Block dotfiles, vendor, storage, .env and backup access. Limit request bodies to a reviewed operational limit (e.g. 5 MB) and request rates at the reverse proxy. Never use artisan serve in production.
2. Create a least-privilege PostgreSQL role and database. Copy .env.example to protected .env (not from a test installation). Set APP_ENV=production, APP_DEBUG=false, public APP_URL, DB values and a strong APP_KEY. Set a separate random SYNC_CURSOR_SECRET or omit it to derive the cursor signing key from APP_KEY. Empty SYNC_CURSOR_SECRET also falls back to APP_KEY.
3. First install only: php artisan key:generate. NEVER regenerate APP_KEY on upgrade; encrypted school card secrets depend on it. Secret management, backup and rotation are infrastructure responsibilities.
4. php artisan migrate --force. Do NOT run migrate:fresh or demo seed. php artisan config:cache and route:cache. Grant write access only to storage/ and bootstrap/cache/. API mutations and sync projections must pass through TerminalOperationService/CanonicalChangeWriter, never direct out-of-band table edits without canonical publication.
5. Provision the real school, books and minimal reader records from the approved EDUS source. The package does not invent a production school or enrollment source. For an existing ACTIVE school, an authorised infrastructure operator issues a one-use 24-hour enrollment code using php artisan edus:enrollment SCHOOL_UUID. Treat the printed code as a secret; never place it in logs/tickets. If cards already exist, restore the original school HMAC key first; generating a new key would break card lookup and is blocked.
6. Terminal first-run: HTTPS Cloud URL + enrollment code + device name. It receives credential and scope automatically. Bootstrap must finish once before offline production work. Invalid/revoked device or old terminal version fails closed without deleting pending operations.
7. Monitor health, HTTP error codes, DB availability, pending/conflicts, disk and backup age. Do not log Authorization headers, request/response bodies, person names, card values, encrypted embeddings or SQL bind values. Exception reporting records only exception class. Disable debug tooling and request-body tracing.
8. Encrypted daily PostgreSQL backups plus APP_KEY/secret-manager recovery are required. Rehearse restore, migration rollback and device credential revocation on staging. Keep prior application package and DB backup; downgrade migrations only with approved restore plan, not destructive reset.

API: /api/terminal/v1/health, enroll, bootstrap, changes, operations, operations/{UUID}. Protected endpoints require Bearer credential, X-EDUS-Sync-Protocol: 1 and X-EDUS-Terminal-Version: 1.1.0 or compatible later. Credential, not body/query school_id, supplies tenant scope. Canonical conflicts are durable receipts and include same-school repair data.

This package contains no .env secrets, test DB, logs, node_modules, Docker volumes or terminal keys. Clean server install, public DNS/TLS, operational approval and production load tests are not claimed by local integration tests.
