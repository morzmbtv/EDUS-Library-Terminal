- В шапке test package постоянно виден бейдж «Тестовый режим». В настройках доступна закрытая по умолчанию панель тестирования: явный capture карты/сканера, local mapping к reader/copy/title, симуляции unknown/error/delay и подтверждённый сброс только test данных. В обычном и production интерфейсе панели нет.
- Добавлены loopback-only Python static service, отдельный Chrome kiosk profile, launcher/diagnostics/desktop entry и [HARDWARE_TEST.md](terminal-test/HARDWARE_TEST.md). Скрипт не переиспользует production config, не останавливает неизвестные процессы и проверяет собственный health endpoint.

Проверки: TypeScript, lint, 57/57 unit/state tests, production build и scan отсутствия demo seed — PASS; terminal-test build/package — PASS. Chromium 1280×800: return workflow 7/7, test panel capture/mapping/refresh persistence 2/2, без console errors, failed requests и external API requests. Скриншоты: [accept-return-list](screenshots/accept-return-list), [terminal-test](screenshots/terminal-test).
## 16 сентября 2026 — список книг в приёме

- После выбора читателя экран приёма сразу загружает его активные выдачи в правую панель «Книги у читателя». Неотмеченные позиции остаются спокойными серыми и не выглядят недоступными; пустой ответ и ошибка локального сервера показаны отдельными состояниями.
- Черновик возврата отделён от активных выдач: сканирование, ручной номер и явный выбор из списка отмечают только нужную позицию «К приёму». Число книг на руках меняется только после общего подтверждения операции.
- Для старого фонда доступен частичный выбор количества; индивидуальный экземпляр отмечается один раз. Отмеченная строка получает синий фон, зелёную проверочную отметку и touch-действия: сведения, изменение количества или «Убрать из приёма».
- Нижняя панель теперь сбрасывает только черновые отметки и запрашивает подтверждение. Она показывает точный счётчик «К приёму: N» и блокирует переход к подтверждению при нуле.
- Контекстная помощь приёма обновлена: она объясняет видимый список книг, сканирование и ручные альтернативы. Ручной поиск читателя, экран карты, выдача и регистрация не менялись.

## 16 сентября 2026 — интеграция поставленной line-анимации карты

- `NfcCardAnimation.vue` заменён прямым Vue-переносом `EDUS_card_line_animation.html`: исходные контуры карты, орнамент, золотой знак, локальный оригинальный логотип EDUS, боковые дуги, scan-line с clip-path, красный error-маркер и зелёный success-маркер сохранены в одной SVG-композиции.
- Компонент остаётся единственной точкой подключения в общем `ReaderIdentification`, поэтому та же анимация используется в выдаче и приёме без изменений навигации, ручного поиска, справки или доменного сценария. `state` продолжает поступать из существующего `nfcState` и mock-адаптера; успех не запускается по таймеру.

Проверки: typecheck, lint, unit/state-тесты и production build — PASS; браузерная проверка source/integration — PASS для выдачи и приёма на 1920×1080 и 1366×768, без console/request errors. ## 17 сентября 2026 — portable TERMINAL TEST package

- `npm run package:terminal-test` дополнительно создаёт `edus-library-terminal-test-portable-<version>.zip`. В его корне находится `EDUS-Library-Test` с видимым ярлыком `EDUS Библиотека — тест.desktop`, папками `launch`, `app`, `assets`, кратким русским руководством и protocol hardware UAT.
- Portable launcher определяет распакованный каталог через путь `.desktop` / `%k`, поддерживает file URI, пробелы и кириллицу, а не использует рабочую директорию, имя пользователя, Downloads или прежний install path. Он показывает GUI-ошибку при отсутствии Python 3 или Google Chrome и не выбирает Chromium автоматически.
- Loopback health endpoint получил instance ID: повторный запуск того же portable package использует только собственный сервис; чужой instance или версия на порту 43180 получают понятную ошибку, не перезапускаются и не завершаются автоматически. Данные продолжат храниться в выделенном test Chrome profile.
- ZIP создаётся Python stdlib с Unix execute attributes для `.desktop`, launcher и сервера; руководство всё равно просит единоразово подтвердить «Разрешить запуск» в GUI, потому что поведение распаковщика и файлового менеджера зависит от Ubuntu shell.

Проверки: terminal-test build/package — PASS; portable archive structure/executable attributes — PASS; распаковка в путь с пробелами и кириллицей — PASS; exact health instance `0`, чужой instance `11` — PASS. Ubuntu graphical-click, reboot, missing-dependency dialogs и actual hardware остаются on-site проверками.
